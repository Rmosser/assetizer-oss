# 根据问题和底稿，写回看计划和写作提示词

用户在一次看一批视频，想弄清一个问题，见下。你看不到视频，只有这期视频的底稿（在最后）。你要先判断这期和问题有多大关系，再写一份“目的提示词”，分两部分：

- **看**：列出要回到原片核对的地方，交给能看图和视频的模型执行。
- **写**：一份写作提示词，交给后面的写作代理，让它用底稿和回看结果写出这期的笔记。

问题：{question}
{notes}

## 底稿怎么读

底稿按时间交错排着三种内容，可信程度不同：

| 行 | 来源 | 可信 | 不可信 |
|---|---|---|---|
| `说：` / `说 mm:ss：` | Whisper 转写 | 讲了什么 | 中文里夹的英文代码、人名、术语常转错；有同音字 |
| `[mm:ss-mm:ss] 类型…`，以及下面的 画面/文字/图形/动作/声音/不确定 | Gemini 看每秒 1 帧的低清代理 | 什么时候是什么场景、操作顺序、大字、图表上的代码 | 小字、读数、价格、型号、数量、左右手。它还会把讲话当字幕写、画面缺失时按声音编画面、把原文改成规范写法。时间比实际早约 2 秒 |
| `高清帧 mm:ss.s：` | 原片全分辨率单帧逐字照抄 | 屏幕文字，时间精确到 0.1 秒 | 图例、坐标轴、数码管这类小字里 5/6、3/8、x/% 会混；每 15 秒左右才取一帧，滚动的列表、一闪而过的框、动画中的数字常错过 |

{brief}

## 先判断：这期和问题有多大关系

- `high`：正面讲了问题的一部分（做法、参数、原因、对比、踩过的坑），能写出有用的笔记。
- `some`：只沾边：零星提到、只有背景，或只讲了问题的一个小角落。
- `none`：和问题无关，或者只是标题沾边。

`none` 时 looks 写空列表，write 写空字符串，reason 用一句话说清这期讲的是什么、为什么和问题无关。

## 看：回看清单

只为问题要用、而底稿定不下来的事实安排回看：

- 要用到的数字、价格、代码、型号、名字：只出现在画面记录或转写里、没有高清帧印证，或者几个来源互相矛盾，就要回看。
- 高清帧已经清楚读到、和转写也对得上的，不用回看。只来自高清帧小字（图例、坐标轴、表格小格）的关键数字，用 zoom 复核一次。
- 转写里问题要用的同音字、术语、人名：先找屏幕上有没有对应的字（烧录字幕、板书、图表、界面、包装），有的合并成一两条 `times` 回看，一次读几处，不要一处一条。
- 价格只问图上印出来的数字：价位线标签、标注文字、表格、图例。不要让它按坐标轴估算某个点、某根 K 线的价位；图上没标的，写作时写“图上没标出”。图例里的开高低收跟着鼠标走，不要问。

选哪种 mode：

| 要看的 | mode | 说明 |
|---|---|---|
| 静止的整屏：表格、列表、幻灯片、标题卡 | frame | start–end 之间取 1–3 张全分辨率帧 |
| 会变的字和数字：滚动的列表、跟着鼠标的标签、动画里的数字、一闪而过的测量框、几张轮换的卡片 | frames | 每隔 `step` 秒（默认 1，最小 0.2）取一张全分辨率帧，最多 8 张；问停稳后的读数。时间段长的拆成几条。安装向导、终端提问这类停留不到 1 秒的画面，用 0.2–0.3 秒的 step 取短段 |
| 几处分散时刻的字：烧录字幕、几张不连续的卡片 | frames，写 `times` | `"times": ["01:02.5", "03:10", …]`，每个时刻取一帧，最多 8 个；不用写 start、end |
| 小区域里的字或读数：仪表、表格某格、图上某个标注 | zoom | 取中点一帧，先定位 target 再放大。target 写清颜色、位置、长相，例如“图右侧蓝色价位线上的数字标签”；附近有几个相像的，写清要哪一个 |
| 动作本身：次数、先后、往哪个方向动 | clip | 原片片段，最长 40 秒，低清。**不能读字和数字**。clip 的回答没有第二个模型复核，所以停在哪、落在哪、谁高谁低、贴没贴住这类位置判断不要用 clip，用 frames 加 second |
| 实物上印的小字：罐身、包装、铭牌、标签（曲面、反光、斜拍） | zoom 加 `"second": true` | 屏幕、幻灯片、板书上的字单次回看就够；实物上的小字单个模型常读错，要两个模型一致 |
| 画面状态：这一刻弹的是哪个框、框里有几项、点没点下、什么时候点的 | frames 加 `"second": true` | 状态一闪就变，单个模型常把前后两刻混在一起 |
| 左右，以及手、手指、脚、身体姿势的细节：哪只手、哪条腿、哪根手指按在哪、握法、角度 | frames 或 zoom，加 `"second": true` | 取几个时刻的全分辨率帧，另一个模型会独立再看一遍 |

每条的字段：

```json
{"id": "L01", "start": "01:43.5", "end": "01:46", "mode": "frame | frames | zoom | clip", "step": 1, "times": ["只在读分散时刻时写"], "second": false, "target": "zoom 时必填：要放大画面里的哪一块", "question": "只问一件具体的事，写清要哪些字段", "why": "底稿里是什么情况，为什么要看"}
```

- start、end 写成底稿里的时间格式（`mm:ss`、`mm:ss.s` 或 `h:mm:ss`），从底稿照抄再加减，不要换算成秒数，换算由代码做。
- 画面记录的时间早约 2 秒，前后各留 2–3 秒。高清帧的时间可以直接用。
- 避开转场：取帧范围不要跨两个镜头的交界；画面记录里写了“切至”“转场”的地方，往后留 1 秒。
- step、times 只在 frames 时写，二选一；second 在问左右和手、脚、姿势细节时写 true。
- question 只问画面上能看到的东西，不要让它复述整段，也不要问讲者说了什么（讲话以转写为准）。
- 最多 25 条，按对问题的重要程度排。`some` 的期只看最要紧的几处。

## 写：写作提示词

写给后面的写作代理。它会拿到：问题、这份写作提示词、底稿、回看结果（每条有 answer、evidence、sure；加了 second 的还有第二个模型独立回答的 answer2、evidence2、sure2）。

写作提示词要写清：

- 笔记的结构：按问题和这期的内容定，写到小标题和字段。笔记是给想弄清这个问题的人看的：先写这期对问题有什么，再写细节；和问题无关的部分不写。
- 每个数字、价格、代码、型号、名字后面标来源，例如 `[12:34 说]`、`[12:34.5 帧]`、`[L03]`。
  - 画面记录里的数字不能单独当来源。
  - 讲者说了什么，以转写为准；画面上是什么，回看和高清帧优先于画面记录。
  - 来源之间冲突时，写出来，并说明取了哪个。
- 回看结果的 sure 是模型自评，不能当可信程度。印在画面上的字和数字，回看读到就能用；左右、手、脚、姿势、位置这类判断，要有两个模型一致的回答（answer 和 answer2）才能用，只有一个回答的（包括 clip 的回答）写“未核实”。两个回答不一致，写“画面看不清，两个模型说法不同”，把两个回答都列出来。
- 没有直接看到的不推断：“第一条”“最后一步”“第几行”“共几项”只在画面完整露出时写；画面只露出一部分的，写“画面露出的第一行是……”。
- 转写同音字按意思改之前，先对屏幕上的字（字幕、板书、图表、界面、包装，看高清帧或回看）；没对上的，保留转写原文并标“未核实”。
- 实物上印的小字（罐身、包装、铭牌）和画面状态（弹的是哪个框、点没点下），和左右一样要两个模型一致才能用。
- 判断“讲者说的和画面对不对得上”时，拿讲者说这句话那一刻（前后 2 秒内）的画面比，不要拿几秒后的画面。
- 操作步骤的先后，按回看和高清帧里的时间排，不按讲者口述或画面记录的顺序猜。
- 来源标在事实真正出现的那一刻。卡片、幻灯片、表格上的内容，标那张画面的时间，不要标讲者提到它的时间。
- 没有可靠来源的，写“未核实”，不要补。
- 只写视频里有的内容，不加写作代理自己的知识和评论。原文没有的数量词、频率词、限定词（“一次”“每次”“都”“只”“大约”）不要加。

## 输出

只输出一个 JSON 对象：

```json
{"fit": "high | some | none", "reason": "一句话：这期讲了什么、和问题是什么关系", "looks": [回看清单], "write": "写作提示词（Markdown）"}
```

不要读别的材料，不要上网，不要找原片或截图。
